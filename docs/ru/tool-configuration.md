# Настройка инструментов

Все инструменты опциональны. Скилл определяет, что доступно, и подстраивает оценку. На этой странице описано, как обнаруживается каждый инструмент, какую конфигурацию он читает и как его настройки влияют на оценку.

## Порядок обнаружения

Для каждого инструмента скилл проверяет доступность в таком порядке:

1. Глобальный бинарник — `which <tool>`
2. Бинарник в vendor — `test -f vendor/bin/<tool>`
3. Composer require-dev — запись в `composer.json`
4. Конфигурационные файлы — специфичные для инструмента файлы в корне проекта

Для Docker-окружений все команды обнаружения выполняются через `docker compose exec -T <service>`.

После обнаружения скилл выводит таблицу:

```
Tool Detection Results:
  Runtime         Docker (php-service via docker/docker-compose.yml)
  composer audit  ✓ (composer 2.7.1)
  PHPStan         ✓ (vendor/bin/phpstan, level 6, phpstan.neon)
  semgrep         ✓ (0.185.0)
  phpcs           ✗ (php-cs-fixer detected as alternative)
  PHPUnit         ✓ (vendor/bin/phpunit, phpunit.xml.dist)
  Coverage driver ✓ (pcov)
  phpmd           ✗ → install: composer require --dev phpmd/phpmd
  ...
```

## Детали по инструментам

### composer audit

**Назначение:** Обнаружение известных CVE-уязвимостей в зависимостях.

**Обнаружение:** `which composer` или `test -f composer.phar`. Для Docker: `$CMD_PREFIX composer --version`.

**Конфигурационные файлы:** Нет. Использует `composer.lock` автоматически.

**Команда:** `composer audit --format=json`

**Влияние на оценку:** Категория Безопасность (0-20). Критические CVE = 0 баллов. Ноль CVE = 20 баллов.

---

### PHPStan

**Назначение:** Статический анализ на типовые ошибки, корректность кода и потенциальные баги.

**Обнаружение:** `which phpstan`, `vendor/bin/phpstan` или в `composer.json` require-dev.

**Конфигурационные файлы:** `phpstan.neon`, `phpstan.neon.dist`, `phpstan.dist.neon`

**Ключевая настройка — `level:`**

Поле `level` в конфигурации PHPStan напрямую влияет на оценку:

| Уровень PHPStan | Влияние на оценку |
|-----------------|-------------------|
| Уровень 6+ с <10 ошибками | Максимум баллов |
| Уровень 4-5 с <50 ошибками | 75% баллов |
| Уровень 1-3 или >100 ошибок | 50% баллов |
| Уровень 0 или >500 ошибок | 25% баллов |

Если конфигурационного файла нет и PHPStan запускается — предполагается уровень 0.

**Команда:** `phpstan analyse --error-format=json`

**Влияние на оценку:** Категория Статический анализ. Если phpmd тоже доступен, PHPStan получает 12 из 20 баллов. Если PHPStan единственный — все 20.

---

### semgrep

**Назначение:** Поиск паттернов безопасности — уязвимости инъекций, захардкоженные секреты, опасные функции.

**Обнаружение:** `which semgrep`. Всегда работает на хосте (читает файлы напрямую), даже в Docker-окружениях.

**Конфигурационные файлы:** Нет. Использует `--config auto` для применения общественных наборов правил.

**Команда:** `semgrep scan --config auto --lang php --json --quiet`

**Установка:** `pip install semgrep`

**Влияние на оценку:** Категория Безопасность вместе с composer audit.

---

### phpcs (PHP_CodeSniffer)

**Назначение:** Соответствие стандартам кодирования (PSR-12, пользовательские наборы правил).

**Обнаружение:** `which phpcs`, `vendor/bin/phpcs` или в `composer.json` require-dev.

**Конфигурационные файлы:** `phpcs.xml`, `.phpcs.xml`, `phpcs.xml.dist`, `.phpcs.xml.dist`

Конфигурация определяет, какой стандарт и набор правил применять. Скилл использует существующую конфигурацию проекта — он не навязывает стандарт по умолчанию.

**Команда:** `phpcs --report=json`

**Влияние на оценку:** Категория Качество кода. Баллы делятся пропорционально с другими доступными инструментами (phpcpd, phploc).

---

### php-cs-fixer

**Назначение:** Альтернатива phpcs для контроля стандартов кодирования.

**Обнаружение:** `vendor/bin/php-cs-fixer` или в `composer.json` require-dev.

**Конфигурационные файлы:** `.php-cs-fixer.dist.php`, `.php-cs-fixer.php`

**Когда используется:** Только если phpcs недоступен. Скилл запускает его в режиме dry-run для подсчёта нарушений без изменения файлов.

**Команда:** `php-cs-fixer fix --dry-run --diff --format=json`

**Влияние на оценку:** Аналогично phpcs — категория Качество кода.

---

### PHPUnit

**Назначение:** Запуск тестов и измерение покрытия строк.

**Обнаружение:** `which phpunit`, `vendor/bin/phpunit` или в `composer.json` require-dev.

**Конфигурационные файлы:** `phpunit.xml`, `phpunit.xml.dist`

**Требует драйвер покрытия:** Xdebug или PCOV должен быть установлен как расширение PHP. Без драйвера покрытия скилл не может измерить покрытие и ставит 0 за категорию Покрытие тестами.

**Команда:** `phpunit --coverage-text --colors=never`

**Влияние на оценку:** Категория Покрытие тестами (0-20).

---

### Codeception

**Назначение:** Альтернативный тестовый фреймворк. Используется, если PHPUnit не является основным.

**Обнаружение:** `vendor/bin/codecept` или в `composer.json` require-dev.

**Конфигурационные файлы:** `codeception.yml`, `codeception.dist.yml`

**Команда:** `codecept run --coverage --coverage-text`

**Влияние на оценку:** Аналогично PHPUnit — категория Покрытие тестами.

Если доступны оба фреймворка, используется тот, у которого больше тестовых наборов в конфигурации.

---

### phpmd (PHP Mess Detector)

**Назначение:** Цикломатическая сложность, нарушения правил дизайна, обнаружение неиспользуемого кода.

**Обнаружение:** `which phpmd`, `vendor/bin/phpmd`.

**Конфигурационные файлы:** `phpmd.xml`, `phpmd.xml.dist`

**Применяемые наборы правил:** `cleancode`, `codesize`, `controversial`, `design`, `naming`, `unusedcode`

**Команда:** `phpmd <source-dirs> json cleancode,codesize,controversial,design,naming,unusedcode`

Директории определяются из PSR-4 autoload в `composer.json`. Запасной вариант: `src/,app/,lib/`.

**Влияние на оценку:** Категория Статический анализ вместе с PHPStan.

---

### phpcpd (Copy/Paste Detector)

**Назначение:** Обнаружение дублированных блоков кода.

**Обнаружение:** `which phpcpd`, `vendor/bin/phpcpd`.

**Конфигурационные файлы:** Нет.

**Команда:** `phpcpd <source-dirs>`

**Влияние на оценку:** Категория Качество кода.

---

### phploc

**Назначение:** Статистика размера кодовой базы — строки кода, средняя длина класса, средняя длина метода.

**Обнаружение:** `which phploc`, `vendor/bin/phploc`.

**Конфигурационные файлы:** Нет.

**Команда:** `phploc <source-dirs>`

**Ключевые метрики для оценки:** Средняя длина класса (LOC) и средняя длина метода (LOC). Меньше = лучше.

**Влияние на оценку:** Категория Качество кода.

---

### pdepend

**Назначение:** Метрики качества ПО и анализ зависимостей.

**Обнаружение:** `which pdepend`, `vendor/bin/pdepend`.

**Конфигурационные файлы:** Нет.

**Примечание:** Обнаруживается, но в текущей версии не используется в оценке напрямую. В будущих версиях метрики pdepend могут быть добавлены.

---

### Драйвер покрытия (Xdebug / PCOV)

**Назначение:** Необходим PHPUnit/Codeception для измерения покрытия строк.

**Обнаружение:** `php -m | grep -iE 'xdebug|pcov'`

**Рекомендация:** PCOV быстрее Xdebug для задач покрытия. Установка: `pecl install pcov`.

Если ни один драйвер не доступен, Покрытие тестами получает 0 баллов с пометкой в отчёте.

---

## Какие инструменты устанавливать первыми

Для максимального охвата оценки с минимальной настройкой:

1. **PHPStan** — включает оценку Статического анализа. `composer require --dev phpstan/phpstan`
2. **PHPUnit** + **PCOV** — включает оценку Покрытия тестами. В большинстве PHP-проектов PHPUnit уже есть.
3. **semgrep** — включает глубокое сканирование Безопасности. `pip install semgrep`
4. **phpcs** или **php-cs-fixer** — включает часть оценки Качества кода.
5. **phpcpd** — включает обнаружение дубликатов в Качестве кода.

composer audit и `composer outdated` встроены в Composer, поэтому категории Безопасность и Зависимости работают без дополнительных установок.
