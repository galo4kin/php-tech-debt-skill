# Справочник проверок

Скилл выполняет два типа анализа: оценку инструментами (автоматическая, числовая) и архитектурный аудит (на основе Claude, поиск паттернов). На этой странице описаны все проверки.

---

## Часть 1: Оценка инструментами

5 категорий, каждая от 0 до 20 баллов, итого 100. Если для некоторых категорий нет инструментов, оценка нормализуется, чтобы итог всегда был из 100.

### Нормализация

```
available_categories = количество категорий, где есть хотя бы 1 инструмент
weight_per_category = 100 / available_categories
weighted_score = (raw_score / 20) * weight_per_category
final_score = сумма всех weighted_scores, округлённая до целого
```

**Пример:** Если инструменты есть только для 3 категорий (Безопасность, Статический анализ, Зависимости) с баллами 18, 12 и 15:

```
weight = 100 / 3 = 33.33
Безопасность:      (18/20) * 33.33 = 30.0
Статический анализ: (12/20) * 33.33 = 20.0
Зависимости:       (15/20) * 33.33 = 25.0
Итого: 75/100
```

---

### Категория 1: Безопасность (0-20)

**Инструменты:** composer audit, semgrep

| Балл | Критерий |
|------|----------|
| 20 | Ноль CVE из composer audit И ноль находок безопасности из semgrep |
| 15 | Только CVE низкой серьёзности, нет критических/высоких находок semgrep |
| 10 | CVE средней серьёзности ИЛИ умеренные находки semgrep |
| 5 | Присутствуют CVE высокой серьёзности |
| 0 | Критические CVE ИЛИ критические находки semgrep |

Если доступен только один инструмент, оценка выставляется только по нему (полные 20 баллов возможны).

**Команды:**
- `composer audit --format=json`
- `semgrep scan --config auto --lang php --json --quiet`

---

### Категория 2: Статический анализ (0-20)

**Инструменты:** PHPStan, phpmd

Когда доступны **оба** инструмента, баллы делятся: PHPStan получает 12, phpmd получает 8.

**PHPStan (0-12):**

| Балл | Критерий |
|------|----------|
| 12 | Уровень 6+, менее 10 ошибок |
| 9 | Уровень 4-5, менее 50 ошибок |
| 6 | Уровень 1-3 ИЛИ более 100 ошибок |
| 3 | Уровень 0 ИЛИ более 500 ошибок |

**phpmd (0-8):**

| Балл | Критерий |
|------|----------|
| 8 | 0 нарушений |
| 6 | Менее 20 нарушений |
| 4 | Менее 100 нарушений |
| 2 | 100 и более нарушений |

Если доступен **один** инструмент — он получает все 20 баллов (пороги масштабируются пропорционально).

**Команды:**
- `phpstan analyse --error-format=json`
- `phpmd <source-dirs> json cleancode,codesize,controversial,design,naming,unusedcode`

Директории определяются из PSR-4 autoload в `composer.json`. Запасной вариант: `src/,app/,lib/`.

Уровень PHPStan читается из `phpstan.neon`, `phpstan.neon.dist` или `phpstan.dist.neon`. Если конфигурации нет, предполагается уровень 0.

### Категория 3: Зависимости (0-20)

**Инструменты:** composer outdated

| Балл | Критерий |
|------|----------|
| 20 | Менее 10% устаревших, нет пробелов в мажорных версиях |
| 15 | Менее 25% устаревших ИЛИ 1-2 пробела в мажорных версиях |
| 10 | Менее 50% устаревших ИЛИ 3+ пробелов в мажорных версиях |
| 5 | Более 50% устаревших |
| 0 | Более 75% устаревших ИЛИ обнаружены заброшенные пакеты |

Также проверяется дата последнего обновления `composer.lock` через `git log -1 --format=%ci composer.lock`. Отмечается, если файл не обновлялся более 6 месяцев.

**Команда:**
- `composer outdated --direct --format=json`

---

### Категория 4: Качество кода (0-20)

**Инструменты:** phpcs (или php-cs-fixer), phpcpd, phploc

Баллы делятся пропорционально между доступными инструментами. Все 3: phpcs ~7, phpcpd ~7, phploc ~6. Два: по 10. Один: все 20.

**phpcs:**

| Балл | Критерий |
|------|----------|
| Полный | 0 нарушений |
| 75% | Менее 50 нарушений |
| 50% | Менее 200 нарушений |
| 25% | 200 и более нарушений |

Если phpcs нет, но есть **php-cs-fixer**: `php-cs-fixer fix --dry-run --diff --format=json` для подсчёта нарушений.

**phpcpd:**

| Балл | Критерий |
|------|----------|
| Полный | 0 клонов |
| 75% | Менее 5 клонов |
| 50% | Менее 20 клонов |
| 25% | 20 и более клонов |

**phploc:**

| Балл | Критерий |
|------|----------|
| Полный | Средний класс < 200 LOC И средний метод < 20 LOC |
| 75% | Средний класс < 300 LOC И средний метод < 30 LOC |
| 50% | Средний класс < 500 LOC И средний метод < 40 LOC |
| 25% | Превышает указанные пороги |

**Команды:**
- `phpcs --report=json`
- `phpcpd <source-dirs>`
- `phploc <source-dirs>`

---

### Категория 5: Покрытие тестами (0-20)

**Инструменты:** PHPUnit или Codeception + драйвер покрытия (Xdebug или PCOV)

| Балл | Критерий |
|------|----------|
| 20 | Более 90% покрытия строк |
| 15 | 70-90% покрытия |
| 10 | 50-70% покрытия |
| 5 | 30-50% покрытия |
| 0 | Менее 30% покрытия |

**Особые случаи:**
- Нет драйвера покрытия (ни Xdebug, ни PCOV): 0 баллов, пометка в отчёте
- Нет тестового фреймворка: 0 баллов, создаётся КРИТИЧЕСКАЯ находка

**Команды:**
- PHPUnit: `phpunit --coverage-text --colors=never`
- Codeception: `codecept run --coverage --coverage-text`

Если доступны оба, используется тот, у которого больше тестовых наборов в конфигурации.

## Часть 2: Архитектурный аудит (9 измерений)

Анализ на основе Claude с использованием `grep`, `rg`, `find` и чтения кода. Каждая находка содержит ссылку `файл:строка`. Если паттерн не найден — он не включается в отчёт.

---

### Измерение 1: Архитектурная деградация

| Паттерн | Как обнаруживается |
|---------|--------------------|
| God-классы (>500 строк) | Список крупнейших файлов, проверка на единственный класс с множеством ответственностей |
| Злоупотребление Service Locator | `Yii::$app->`, `app()`, `Container::get()` вне конфигурации DI |
| Циклические зависимости пространств имён | Анализ `use`-выражений: если пространство A импортирует из B и B из A |
| Мёртвый код | Неиспользуемые `use`-выражения, классы без ссылок |
| Контроллеры с бизнес-логикой | Методы контроллеров >30 строк с запросами к БД или сложной логикой |

---

### Измерение 2: Эрозия единообразия

| Паттерн | Как обнаруживается |
|---------|--------------------|
| Несколько HTTP-клиентов | Одновременное использование GuzzleHttp, Http, file_get_contents для HTTP, curl_init |
| Разные подходы к валидации | Validator::, ->validate(), new Validator в одном проекте |
| Смешанная автозагрузка | PSR-4 и classmap/files в composer.json одновременно |
| Непоследовательное именование | camelCase и snake_case методы в одном слое |
| Разные форматы конфигурации | .php, .yml, .yaml, .json, .ini, .xml для одной и той же цели |

---

### Измерение 3: Долг типизации

| Паттерн | Как обнаруживается |
|---------|--------------------|
| Отсутствие `declare(strict_types=1)` | Подсчёт файлов с и без объявления, отчёт о соотношении |
| Отсутствие возвращаемых типов | Публичные методы без `: ReturnType` перед `{` |
| `mixed` без валидации | `rg 'mixed \$'`, проверка тела метода на наличие проверок типа |
| `@var` без объявления типа | Свойства с аннотациями `@var`, но без PHP-типов |
| Нетипизированные свойства | `(public|protected|private) $` без указания типа |

---

### Измерение 4: Тестовый долг

| Паттерн | Как обнаруживается |
|---------|--------------------|
| Пробелы в покрытии | Критические пути (контроллеры, сервисы) с низким/нулевым покрытием |
| Тесты проверяют реализацию | `->expects(.*exactly(`, `->method(` в тестовых файлах |
| Пропущенные/закомментированные тесты | `@skip`, `markTestSkipped`, `markTestIncomplete` |
| Отсутствие интеграционных тестов | В директории тестов только юнит-тесты с полным мокированием |
| Тесты без утверждений | Тестовые методы без `$this->assert*` или `$this->expect*` |

---

### Измерение 5: Долг зависимостей

| Паттерн | Как обнаруживается |
|---------|--------------------|
| CVE | Из оценки безопасности (Фаза 3) |
| Dev-пакеты в require | phpunit, phpstan, phpcs, mockery, faker в `require` вместо `require-dev` |
| Неиспользуемые пакеты | Пакеты в require, чьё пространство имён не импортируется в коде |
| Заброшенные пакеты | Флаги заброшенности от composer |
| Проблемы с версией PHP | Слишком свободное (`>=7.0`), слишком строгое (`=8.1.5`) или не совпадает с рантаймом |

---

### Измерение 6: Производительность

| Паттерн | Как обнаруживается |
|---------|--------------------|
| N+1 запросы | Вызовы ORM/БД внутри тел `foreach` циклов |
| `file_get_contents()` для HTTP | `file_get_contents` с URL, начинающимся на http |
| Отсутствие индексов БД | Миграции с внешними ключами без объявления индексов |
| Синхронный ввод-вывод в пути запроса | `sleep()`, `file_get_contents()`, `curl_exec()` в контроллерах |
| Большие массивы без генераторов | `array_map`/`array_filter`/`array_merge` на потенциально больших наборах данных |

---

### Измерение 7: Обработка ошибок

| Паттерн | Как обнаруживается |
|---------|--------------------|
| Пустые catch-блоки | Catch с пустым телом |
| Catch без логирования/повторного выброса | Catch-блоки, которые не логируют и не выбрасывают исключение повторно |
| Слишком широкие catch | `catch (\Exception` или `catch (\Throwable`, когда подходит конкретный тип |
| Тихие ошибки | `return null`/`return false` в путях ошибок без логирования |
| Оператор подавления ошибок | `@file`, `@fopen`, `@mail`, `@unlink`, `@mkdir` |

---

### Измерение 8: Гигиена безопасности

| Паттерн | Как обнаруживается |
|---------|--------------------|
| Прямой доступ к суперглобалам | `$_GET[`, `$_POST[`, `$_REQUEST[`, `$_SERVER[` вне бутстрапа фреймворка |
| Конкатенация строк в SQL | Конкатенация строк с ключевыми словами SQL (SELECT, INSERT и т.д.) |
| Опасные функции | `eval()`, `extract()`, `exec()`, `system()`, `passthru()`, `shell_exec()` |
| Захардкоженные учётные данные | `password =`, `api_key =`, `secret =`, `token =` со строковыми значениями |
| Слабое хеширование паролей | `md5()` или `sha1()` для хеширования паролей |
| Отсутствие CSRF-защиты | Формы/POST-эндпоинты без валидации CSRF-токена |
| Непроверенные редиректы | Редиректы с использованием значений `$_GET`/`$_POST` |

---

### Измерение 9: Дрейф документации

| Паттерн | Как обнаруживается |
|---------|--------------------|
| Несовпадение типов @param | Сравнение аннотаций `@param` с реальными сигнатурами методов |
| Публичные методы без докблоков | `public function` без предшествующего блока `/**` |
| README не соответствует реальности | Сравнение инструкций README с реальной структурой проекта |
| Устаревшие TODO/FIXME | `TODO`/`FIXME`/`HACK`/`XXX` + `git blame` для проверки возраста (>6 месяцев = устаревший) |
