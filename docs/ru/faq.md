# FAQ

## «No PHP runtime detected»

Скилл не нашёл PHP на хосте (`which php` ничего не вернул) и не нашёл запущенный Docker-контейнер с PHP.

**Решения:**
- Установите PHP на свою машину
- Если используете Docker: убедитесь, что контейнер запущен (`docker compose up -d`) и что файл compose находится в корне проекта или в директории `docker/`
- Если PHP находится в другом месте: скилл всё равно запустит архитектурный анализ через чтение файлов — оценка инструментами будет пропущена

---

## «Балл кажется низким, а код нормальный»

Несколько возможных причин:

**Отсутствующие инструменты.** Если инструменты есть только для 2 из 5 категорий, нормализация делает каждую категорию более весомой. Одна слабая область непропорционально снижает итог. Установите больше инструментов для сбалансированной картины.

**Строгие критерии.** Пороги оценки намеренно требовательны. Например, Статический анализ даёт максимум баллов только при уровне PHPStan 6+ с менее чем 10 ошибками. Проект на уровне 5 с 30 ошибками получает 75% — хорошо, но не максимум.

**Устаревшие зависимости.** Категория Зависимости проверяет, какой процент прямых зависимостей устарел. Даже если проект работает нормально, много устаревших пакетов снижают балл.

Проверьте раздел «Отсутствующие инструменты» в отчёте, чтобы узнать, что установить для более глубокого анализа.

---

## «Как быстрее всего улучшить балл?»

1. **Установите недостающие инструменты.** Каждый новый инструмент открывает категорию оценки или добавляет глубину к существующей. Начните с PHPStan и PCOV.
2. **Исправьте быстрые исправления.** В отчёте перечислены находки, которые занимают менее 2 часов и дают ощутимый результат.
3. **Поднимите уровень PHPStan.** Переход с уровня 0 на уровень 4 может удвоить оценку Статического анализа.
4. **Обновите зависимости.** Запустите `composer update` для патч/минорных обновлений. Каждый обновлённый пакет улучшает оценку Зависимостей.

## «Можно ли проверить только часть кодовой базы?»

Да. Передайте аргумент с директорией:

```
/php-tech-debt-audit src/Billing/
```

Это ограничит фазу ориентации (структура каталогов, крупнейшие файлы) указанной директорией. Оценка инструментами по-прежнему работает на всём проекте, потому что инструменты вроде PHPStan и phpcs используют конфигурацию уровня проекта.

## «Как часто запускать аудит?»

**Рекомендуемая периодичность:**
- Раз в спринт при активной разработке
- Перед крупными релизами
- После масштабного рефакторинга
- При знакомстве с незнакомой кодовой базой

Отслеживание между запусками строит историю трендов, поэтому регулярные запуски дают полезную динамику.

## Docker: «Container not running»

Скилл нашёл `docker-compose.yml`, но PHP-контейнер не запущен.

**Решение:** Запустите контейнер перед запуском аудита:

```bash
docker compose up -d
```

Или, если файл compose в поддиректории:

```bash
docker compose -f docker/docker-compose.yml up -d
```

---

## Docker: «PHP service not found»

Скилл не смог определить, какой сервис в compose-файле запускает PHP. Он ищет сервисы со словом `php` в имени.

**Решение:** Убедитесь, что имя вашего PHP-сервиса содержит слово «php» (например, `php`, `php-fpm`, `app-php`). Если у сервиса другое имя, скилл может не обнаружить его автоматически.

## Большие репозитории (>500 PHP-файлов)

Для больших кодовых баз скилл автоматически:

1. Определяет модули или директории верхнего уровня
2. Запускает параллельные подагенты — по одному на модуль для архитектурного аудита (Фаза 4)
3. Объединяет результаты в единый отчёт

Оценка инструментами (Фаза 3) всегда выполняется централизованно на всём проекте. Параллелится только архитектурный аудит.

Это поведение автоматическое — настройка не требуется.
