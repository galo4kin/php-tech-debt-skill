# Как читать отчёт

После завершения аудита скилл записывает `TECH_DEBT_AUDIT.md` в корень проекта. На этой странице объясняется каждый раздел отчёта.

---

## Краткое резюме (Executive Summary)

Два-три предложения об общем здоровье проекта, главной проблеме и рекомендуемом первом действии. Этот раздел можно показать заинтересованным лицам, которые не будут читать полный отчёт.

---

## Карточка здоровья (Health Score Card)

Таблица с 5 категориями оценки:

| Колонка | Значение |
|---------|----------|
| Category | Безопасность, Статический анализ, Зависимости, Качество кода или Покрытие тестами |
| Raw Score | Набранные баллы из 20 для этой категории |
| Weight | Процентный вес после нормализации (выше, если у меньшего числа категорий есть инструменты) |
| Status | ✓ (15-20, здоров), ⚠ (8-14, требует внимания), ✗ (0-7, критично) |
| Tools Used | Какие инструменты предоставили данные для этой категории |

Общий балл вверху — нормализованное значение из 100.

### Отсутствующие инструменты

Перечислены под карточкой оценки. Для каждого отсутствующего инструмента показано, что он проверяет и как его установить. Установка дополнительных инструментов даёт более глубокий анализ при следующих запусках.

---

## Архитектурная ментальная модель

Резюме в 1-2 абзаца: что делает приложение, его архитектура (монолит, модульный монолит, микросервис), используемый фреймворк и паттерны, заметные структурные решения. Этот раздел пишется во время фазы ориентации, до начала анализа.

---

## Результаты инструментов

Подробный вывод для каждой категории:

- **Безопасность:** Список CVE из composer audit (ID рекомендации, пакет, серьёзность, затронутая версия). Находки semgrep со ссылками файл:строка.
- **Статический анализ:** Ошибки PHPStan, сгруппированные по файлам. Нарушения phpmd по правилам.
- **Зависимости:** Таблица устаревших пакетов с текущей версией, последней версией и типом разрыва (мажорный/минорный/патч). Заметки о возрасте composer.lock.
- **Качество кода:** Сводка нарушений phpcs. Список клонов phpcpd. Статистика размера phploc.
- **Покрытие тестами:** Процент покрытия. Список критических путей (контроллеры, сервисы) с низким или нулевым покрытием.

---

## Архитектурные находки

Основная таблица находок:

| Колонка | Значение |
|---------|----------|
| ID | Уникальный идентификатор (F001, F002, ...). Стабилен между запусками. |
| Category | К какому из 9 измерений аудита относится |
| File:Line | Точное место в кодовой базе |
| Severity | `critical`, `high`, `medium` или `low` |
| Effort | Оценка часов на исправление |
| Status | `ACTIVE`, `NEW`, `RESOLVED` или `SHIFTED` (при повторных запусках) |
| Description | В чём проблема |
| Recommendation | Как исправить (конкретно и в рамках задачи, без предложений переписать) |

Находки отсортированы по серьёзности по убыванию, затем по трудозатратам по возрастанию (самые дешёвые исправления первыми в каждом уровне серьёзности).

---

## Топ-5 приоритетов

5 наиболее важных находок, ранжированных по серьёзности, умноженной на эффективность трудозатрат (высокая серьёзность + низкие трудозатраты = высокий приоритет). Каждая с кратким обоснованием выбора.

---

## Быстрые исправления (Quick Wins)

Находки, которые можно исправить менее чем за 2 часа и которые дают ощутимый результат. Предназначены для первоочерёдного исправления — видимое улучшение при минимальных вложениях.

---

## Выглядит плохо, но всё нормально

Паттерны, которые выглядят проблемными, но являются осознанными дизайн-решениями или допустимыми компромиссами. Например, god-класс, который на самом деле является структурированным фасадом, или `eval()`, используемый в изолированном контексте шаблонизации. Каждая запись объясняет, почему это допустимо.

Этот раздел предотвращает «исправление» того, что не сломано, будущими разработчиками.

---

## Открытые вопросы

Неопределённости, требующие участия мейнтейнеров. Паттерны, где намерение неясно — скилл отмечает их здесь, вместо того чтобы делать предположения о том, являются ли они проблемами.

---

## Приложение: Инструменты и версии

Таблица каждого инструмента, запущенного во время аудита, его версия и точная использованная команда.

---

## Приложение: Базовые метрики

YAML-блок с числовыми значениями текущего запуска:

```yaml
last_run: "2026-05-12"
score: 72
security_raw: 18
static_analysis_raw: 14
dependencies_raw: 12
code_quality_raw: 16
test_coverage_raw: 12
findings_total: 47
findings_critical: 2
findings_high: 8
findings_resolved_cumulative: 12
phpstan_level: 6
phpstan_errors: 23
coverage_percent: 68.5
```

Этот блок машиночитаем и предназначен для автоматизации, интеграции с CI или скриптов отслеживания трендов.

## Ранее исправленные

Свёрнутый раздел в конце, содержащий находки из предыдущих запусков, которые больше не обнаруживаются. Каждая показывает оригинальный ID находки, описание и дату исправления. Это сохраняет историю аудита.

---

## Статусы при повторном запуске

Когда скилл запускается на проекте, в котором уже есть `TECH_DEBT_AUDIT.md`:

| Статус | Значение |
|--------|----------|
| **ACTIVE** | Ранее обнаруженная находка по-прежнему присутствует на том же месте |
| **RESOLVED** | Ранее обнаруженная находка больше не определяется. Перемещается в раздел «Ранее исправленные». |
| **SHIFTED** | Та же проблема существует, но номер строки изменился (код был добавлен/удалён выше). Ссылка на строку обновляется, ID находки сохраняется. |
| **NEW** | Проблема, обнаруженная в текущем запуске, которой не было в предыдущем. Получает следующий доступный ID. |

Строка оценки показывает дельту: `72/100 (+8 since 2026-03-15)`.
